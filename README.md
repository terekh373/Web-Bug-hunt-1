# Полювання на помилки №1 — «Кав'ярня „Дедлайн“»

Статичний сайт на три сторінки (`index.html`, `menu.html`, `contacts.html`) з одним `style.css`. У CSS **шість помилок**. Кожна дає видимий симптом. Ваша задача — не «зробити красиво», а для кожного симптому **знайти причину інструментами, виправити її і пояснити**.

## Правила

1. Працюємо **без ШІ-агента** для пошуку причин. Можна відкрити MDN. Агентом можна перевірити формулювання причини після того, як ви її знайшли самі, — але не просити «знайди баг» і не просити переписати CSS.
2. Виправлення — мінімальне: змінити або видалити правило-винуватця. Не додавати `!important`, не переписувати файл, не дописувати нові правила «поверх».
3. Робота у гілці `bug-hunt`, один коміт на кожну помилку (`fix: №N — коротко`), потім pull request у власний форк із заповненим `DIAGNOSIS.md`.
4. Перевіряти на двох ширинах: 1440px і 360px (Device toolbar або реальний телефон). Після кожного виправлення — переконатися, що не зламалося щось інше.

## Симптоми (у рекомендованому порядку)

| № | Сторінка | Що не так |
|---|---|---|
| 1 | усі | Посилання в шапці мають бути білими на темному тлі — а вони темні й нечитабельні. *(розібрано на демо)* |
| 2 | усі, 360px | На вузькому екрані сторінка **не адаптується**: шапка, картки, меню і підвал лишаються «десктопними», хоча медіазапит у файлі є. |
| 3 | головна | Картки «Чому до нас» на десктопі **наїжджають одна на одну**; на 360px з'являється горизонтальний скрол. |
| 4 | усі | Три колонки підвалу (Адреса / Години / Зв'язок) на широкому екрані стоять **стовпчиком**, а мають бути в ряд. |
| 5 | меню | Позиції меню мають бути **у дві колонки** на десктопі, а йдуть одним стовпчиком. |
| 6 | меню | Ціна в кожній позиції має бути **притиснута праворуч**, а стоїть одразу після назви. |

Порядок не випадковий: №2 варто виправити раніше за №3, інакше на 360px ви побачите обидва симптоми разом і буде важко зрозуміти, що саме полагодили.

## Метод (той самий, що на демо)

1. **Симптом** — одна фраза: що бачу і на якій ширині.
2. **Інструмент** — Elements → потрібний елемент → Styles / Computed / Layout. Що саме подивитись — у листі діагностики.
3. **Причина** — не «не працює», а *чому*: специфічність, box-sizing, умова медіазапиту, відсутній контекст flex/grid, невалідна властивість…
4. **Виправлення** — мінімальний diff.
5. **Перевірка** — 1440px і 360px, усі три сторінки.

Підказка на весь курс: у панелі Styles закреслене правило — програло; властивість зі значком «⚠» — браузер її не зрозумів і проігнорував; властивості flex/grid без відповідного `display` у контейнері — нічого не роблять.

## Що здати

Pull request у свій форк з:
- шістьма комітами (або мінімум п'ятьма — №1 можна взяти з демо);
- заповненим `DIAGNOSIS.md` на кожну помилку;
- двома скріншотами головної (1440 і 360) після всіх виправлень.

Орієнтовний час: 90 хвилин на п'ять помилок (№2–№6).
